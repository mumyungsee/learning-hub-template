민지는 코딩을 배운 적이 없는 고객 응대 담당자입니다. 비슷한 예약 문의에 매번 답변을 새로 쓰는 일이 지겨워서, 오늘 처음으로 AI와 작은 업무 도구를 만들어봅니다.

여기서는 결과만 설명하지 않습니다. **민지가 무엇을 몰라서 어떻게 묻는지, 실제로 어떤 프롬프트를 입력하는지, AI의 답을 보고 무슨 판단을 하는지**를 대화 순서대로 따라갑니다.

## 프롤로그 · 민지는 AI에게 먼저 물어봅니다

민지는 강사가 알려준 학습허브 템플릿 주소만 가지고 있습니다. 어디서 시작해야 할지 몰라 Codex에 이렇게 입력합니다.

**민지**

```text
나는 코딩을 처음 해. 오늘 이 학습허브 템플릿으로
내 업무에 쓸 작은 도구를 만들어보고 싶어.
https://github.com/mumyungsee/learning-hub-template

그런데 지금 뭘 먼저 설치해야 하는지도 모르겠어.
이 작업을 시작하려면 무엇이 필요한지 쉬운 말로 알려주고,
내 컴퓨터가 준비됐는지 네가 직접 확인해줘.
```

**AI**

> Git과 GitHub CLI는 템플릿을 내 GitHub 계정과 컴퓨터로 가져오는 데 필요합니다. Node.js와 npm은 가져온 학습허브를 컴퓨터에서 실행하는 데 필요합니다. 먼저 네 가지가 있는지 확인하겠습니다.

민지는 아직 명령어를 외우지 않았습니다. **모르는 상태를 그대로 말하고, 다음 행동을 AI에게 물어보는 것**으로 작업을 시작했습니다.

## 준비 · 계정과 도구 세팅

### 장면 1 · AI에게 설치 여부를 확인시킵니다

필요한 이유를 들은 민지는 확인과 설치도 AI에게 맡겨보기로 합니다.

**민지**

```text
그러면 아래 순서대로 네가 직접 확인해줘.

1. Git 설치 여부
2. GitHub CLI 설치와 로그인 여부
3. Node.js와 npm 설치 여부
4. 지금 네가 작업할 수 있는 폴더

빠진 것이 있으면 추측하지 말고 최신 공식문서를 확인해줘.
명령어를 나한테 복사해서 실행하라고 하지 말고 네가 직접 진행해줘.
브라우저 로그인이나 관리자 권한처럼 내가 해야 하는 것만 알려줘.
끝났다고 말하기 전에 버전과 로그인 결과를 다시 확인해줘.
```

AI가 컴퓨터를 확인합니다.

```text
Git: 설치됨
GitHub CLI: 설치되지 않음
Node.js·npm: 설치되지 않음
작업 폴더: 열려 있음
```

**AI**

> GitHub CLI와 Node.js를 설치해야 합니다. 공식 설치 안내를 확인했습니다. 설치 중 Windows 권한 창이 뜨면 민지님이 승인해야 합니다. 진행할까요?

**민지**

```text
응, 설치해줘. 지우거나 보안 설정을 바꾸는 일은 하지 말고,
내 승인이 필요한 순간에만 멈춰서 알려줘.
```

AI가 설치를 시작하고, 권한 창이 뜨자 민지가 한 번 승인합니다. 설치가 끝난 뒤 AI는 말로만 “됐습니다”라고 하지 않고 실제 버전을 다시 보여줍니다.

```text
git: 확인 완료
gh: 확인 완료
node: 확인 완료
npm: 확인 완료
```

명령어는 AI가 실행했지만, **설치 여부를 결정하고 권한을 승인하고 결과를 확인한 사람은 민지**입니다.

### 장면 2 · GitHub 로그인이 안 된 것을 발견합니다

도구는 설치됐지만 GitHub 계정은 아직 연결되지 않았습니다.

**AI**

> `gh`는 설치됐지만 로그인되어 있지 않습니다. 브라우저 인증이 필요합니다.

민지는 낯선 인증 화면을 보고 다시 묻습니다.

**민지**

```text
이 화면에서 뭘 눌러야 하는지 모르겠어.
공식 GitHub 안내를 확인해서 지금 내가 해야 할 것만 한 단계씩 알려줘.
비밀번호나 인증번호는 네가 대신 입력하지 마.
```

AI가 브라우저를 열고, 민지가 직접 로그인과 승인을 마칩니다. AI는 다시 로그인 상태를 확인합니다.

```text
GitHub 계정: minji
로그인 상태: 정상
저장소 작업 권한: 확인됨
```

설치·로그인처럼 틀리면 뒤가 전부 막히는 일은 **“공식문서를 찾아 정확히 알려줘”**라고 요청합니다. 이것이 민지가 처음 사용한 낙법입니다.

## 시작 1 · 템플릿으로 내 저장소 만들기

### 장면 3 · 포크가 아니라 독립된 비공개 프로젝트를 만듭니다

이제 민지는 수업 자료에 있는 프롬프트를 붙여넣습니다.

**민지**

```text
아래는 오늘 사용할 학습허브 템플릿 저장소야.
https://github.com/mumyungsee/learning-hub-template

이 템플릿으로 내 GitHub 계정에 `my-learning-hub`라는 새 저장소를 만들고
지금 작업 폴더로 가져와줘.

- 반드시 비공개(private) 저장소로 만들기
- 먼저 내 GitHub 로그인을 확인하기
- 포크하지 말고 템플릿으로 독립된 새 저장소 만들기
- 같은 이름의 폴더나 저장소가 있으면 덮어쓰지 말고 알려주기
- 완료 전에 저장소가 private인지, 컴퓨터에 폴더가 생겼는지,
  내 GitHub 저장소와 연결됐는지 직접 확인하기
```

**AI**

> 포크는 원본과 관계를 유지하는 복사이고, 템플릿은 같은 뼈대로 새 프로젝트를 시작하는 방식입니다. 이번에는 민지님의 독립 프로젝트이므로 템플릿으로 만들겠습니다.

AI는 GitHub CLI를 사용해 저장소를 만들고 컴퓨터로 가져옵니다.

```text
GitHub 저장소: minji/my-learning-hub
공개 범위: PRIVATE
내 컴퓨터 폴더: my-learning-hub
원격 연결: minji/my-learning-hub
```

민지는 GitHub 화면에서 자물쇠 표시를 보고 비공개 저장소가 맞는지 직접 확인합니다.

### 장면 4 · README를 읽히고 첫 화면을 엽니다

폴더는 생겼지만 아직 웹사이트가 보이지 않습니다. 민지는 새로 생긴 `my-learning-hub` 폴더를 Codex에서 열고 요청합니다.

**민지**

```text
이 폴더의 README.md를 먼저 읽어줘.
필요한 부품을 설치하고 학습허브를 내 컴퓨터에서 미리보기로 띄워줘.
오류가 나면 숨기지 말고 보여주고, 설치가 끝나면 내가 열 주소를 알려줘.
```

**AI**

> README를 읽었습니다. 이 사이트는 Node.js와 npm을 사용합니다. 필요한 부품을 설치한 뒤 미리보기를 실행하겠습니다.

잠시 뒤 AI가 주소를 알려줍니다.

```text
미리보기 주소: http://localhost:4321
```

민지가 주소를 열자 ‘내 학습허브’ 첫 화면이 나타납니다. 아까 Node.js와 npm을 준비한 이유가 이제 실제 화면과 연결됩니다.

## 시작 2 · 나를 아는 학습메이트 만들기

### 장면 5 · AI가 민지를 한 번에 하나씩 인터뷰합니다

첫 화면은 열렸지만 AI는 아직 민지가 누구인지 모릅니다. 민지는 학습메이트 만들기 프롬프트를 입력합니다.

**민지**

```text
오늘부터 너는 내 AI 학습메이트야.
먼저 이 폴더의 README.md와 `.claude/skills/` 안의 설명서 목록을 읽어줘.

아래 네 가지를 한 번에 하나씩 질문해줘.
1. 네 이름과 나를 부르는 방식
2. 내가 하는 일과 자주 반복하거나 불편한 업무
3. 오늘 AI로 해결해 보고 싶은 것
4. 내가 컴퓨터와 AI를 어느 정도 써봤는지

내 답을 임의로 보태지 말고 정리한 뒤 저장하기 전에 먼저 보여줘.
```

AI가 첫 번째 질문부터 시작합니다.

**AI**

> 저를 어떤 이름으로 부르고 싶고, 저는 민지님을 어떻게 부르면 될까요?

**민지**

```text
너는 ‘모아’라고 부를게. 나는 ‘민지님’이라고 불러줘.
너무 딱딱하지 않게 말해줘.
```

**AI**

> 민지님은 어떤 일을 하고, 요즘 가장 반복되거나 불편한 업무는 무엇인가요?

**민지**

```text
고객 예약과 이용 문의에 답하는 일을 해.
비슷한 질문인데도 매번 답을 새로 쓰고,
예약 변경 때 확인할 내용을 빼먹을까 봐 신경 쓰여.
```

**AI**

> 오늘 AI로 해결해보고 싶은 것은 무엇인가요?

**민지**

```text
아직 정확히 뭘 만들어야 할지는 모르겠어.
반복 문의 답변을 조금이라도 줄일 수 있는 걸 만들고 싶어.
```

**AI**

> 컴퓨터와 AI는 어느 정도 사용해봤나요?

**민지**

```text
윈도우를 쓰고 있고 ChatGPT에 질문만 해봤어.
코딩, GitHub, 터미널은 오늘이 처음이야.
```

AI는 바로 파일을 만들지 않고 먼저 정리해서 보여줍니다. 민지는 AI가 덧붙인 “예약 시스템 관리자”라는 표현을 발견합니다.

**민지**

```text
나는 예약 시스템 관리자는 아니고 고객 문의에 답하는 담당자야.
그 부분만 고치고, 나머지는 지금 정리한 내용대로 저장해줘.
```

AI가 `SOUL.md`, `USER.md`, `AGENTS.md`를 만들고, 다른 AI 도구도 같은 규칙을 읽도록 연결 파일을 만듭니다.

```text
SOUL.md: 학습메이트 ‘모아’의 이름·말투·행동 원칙
USER.md: 민지의 역할·불편한 업무·설명 눈높이
AGENTS.md: 어떤 AI도 지켜야 할 공통 작업 규칙
CLAUDE.md·GEMINI.md: AGENTS.md를 읽게 하는 연결 파일
```

학습메이트는 민지를 마음대로 추측해 기억하는 존재가 아니라, **민지가 확인한 내용을 파일에서 읽고 돕는 AI**입니다.

### 장면 6 · 새 대화에서도 정말 아는지 확인합니다

민지는 같은 폴더에서 새 대화를 엽니다. 방금 전 대화가 없는 상태에서 확인 프롬프트를 입력합니다.

**민지**

```text
이 도구가 자동으로 읽는 프로젝트 지침이 있으면 먼저 따르고,
없거나 모르겠으면 AGENTS.md를 직접 읽어줘.
네 이름과 내가 하는 일, 나를 도울 때 지킬 규칙 세 가지를 알려줘.
```

**새 대화의 AI ‘모아’**

> 저는 모아이고 민지님을 돕는 학습메이트입니다. 민지님은 고객 예약과 이용 문의에 답하는 담당자입니다. 어려운 말은 쉽게 풀고, 민지님이 말하지 않은 업무는 지어내지 않으며, 삭제·덮어쓰기·공개 전에는 먼저 확인하겠습니다.

민지는 이제부터 막힐 때마다 모아에게 모르는 상태 그대로 물어볼 수 있습니다.

## 계획 · 학습메이트와 오늘 만들 크기 정하기

### 장면 7 · “뭘 만들어야 할지도 모르겠어”라고 말합니다

민지는 자동화를 하고 싶지만 구체적인 결과물은 떠오르지 않습니다. 예전 같으면 여기서 멈췄겠지만, 이제 모아에게 문제를 발견하는 일부터 맡깁니다.

**민지**

```text
모아야, 반복 문의를 줄이고 싶지만 뭘 만들어야 할지는 모르겠어.
`.claude/skills/프로젝트발견/SKILL.md`를 읽고,
내가 오늘 풀 업무 문제를 고를 수 있게 질문해줘.

질문은 한 번에 하나씩, 최대 세 개만 해줘.
내가 답하기 어렵다면 예시를 보여줘.
```

모아는 이미 `USER.md`에서 민지의 일을 읽었기 때문에 엉뚱한 아이디어부터 내놓지 않습니다.

**모아**

> 반복 문의 중에서 시간이 가장 많이 들거나 빠뜨리기 무서운 것은 무엇인가요?

**민지**

```text
예약 시간 변경 문의야. 답변하기 전에 꼭 확인해야 할 게 여러 개라서 어려워.
```

**모아**

> 문의 내용을 넣었을 때 어떤 결과가 나오면 바로 써볼 수 있을까요?

**민지**

```text
먼저 확인할 항목이 나오고, 그 아래에 고객에게 보낼 답변 초안이 나오면 좋겠어.
자동으로 보내지는 건 싫고 내가 읽고 고칠 거야.
```

**모아**

> 실제 고객 정보 대신 가상 문의로 시험해도 될까요?

**민지**

```text
응. 이름이나 전화번호 없는 가상 문의로 해줘.
```

학습메이트가 민지를 대신해 답을 만든 것이 아니라, **민지가 답할 수 있도록 한 번에 하나씩 질문해 문제를 선명하게 만들었습니다.**

### 장면 8 · 프로젝트 카드와 미니 PRD를 문서로 남깁니다

대화로 정한 내용이 사라지지 않게 민지는 다음 프롬프트를 입력합니다.

**민지**

```text
지금 답한 내용으로 문서를 두 개 만들어줘.

1. 프로젝트 카드 — 누가 어떤 문제를 겪고 무엇이 나오면 좋은지
2. 미니 PRD — 60분 안에 만들 입력 → 출력 한 장면,
   눈으로 확인할 완료 기준, 오늘 만들지 않을 것, 가상 샘플 데이터

바로 만들기 시작하지 말고 문서 내용을 먼저 보여줘.
내가 말하지 않은 기능은 넣지 마.
```

모아의 첫 계획에는 로그인, 고객 데이터베이스, 자동 발송 기능이 들어 있습니다. 민지는 60분 안에 끝낼 수 있을지 의심합니다.

**민지**

```text
이건 오늘 60분 안에 하기에는 너무 큰 것 같아.
나는 자동 발송도 원하지 않았어.
가상 문의 하나를 넣으면 확인할 점과 답변 초안이 나오는 장면만 남겨줘.
```

모아가 범위를 줄여 다시 보여줍니다.

```text
입력: “내일 오전 예약을 오후로 바꾸고 싶어요.”
출력: 확인할 항목 3개 + 사람이 검토할 답변 초안
완료 기준: 브라우저에서 같은 샘플을 두 번 실행해 결과 확인
오늘 안 함: 로그인, 고객 DB, 실제 개인정보, 자동 발송
```

민지가 “이대로 저장해줘”라고 승인하자 프로젝트 카드와 미니 PRD가 학습허브에 생깁니다. 이제 다음 대화도 목표와 범위를 원문에서 읽을 수 있습니다.

## 제작 · 작동하는 첫 조각 만들기

### 장면 9 · 문서를 읽히고 작은 단계부터 시작합니다

민지는 방금 만든 문서가 다음 작업의 출발점이 되도록 요청합니다.

**민지**

```text
방금 만든 프로젝트 카드와 미니 PRD, 현재 폴더 상태를 읽고 이어서 만들어줘.
남은 시간은 60분이야.

가상 문의 하나를 넣으면 확인할 점과 답변 초안이 나오는
핵심 장면 하나만 만드는 데 집중해줘.
한 번에 다 만들지 말고 작은 단계 하나를 만든 뒤 실제로 확인해줘.
30분이 지나도 한 번도 작동하지 않으면 기능을 더 줄여줘.

사이트를 고치기 전에 `.claude/skills/사이트고치기/SKILL.md`를 읽고,
끝났다고 말하기 전에 미리보기에서 직접 실행한 뒤
`npm run build`와 `npm run check`까지 확인해줘.
```

**모아**

> 먼저 가상 문의와 기대 결과를 고정하고, 그다음 입력 칸과 결과 칸, 마지막으로 버튼을 연결하겠습니다. 첫 단계가 끝날 때마다 화면을 확인하겠습니다.

민지는 계획을 보고 “진행해줘”라고 답합니다. 잠시 뒤 첫 화면이 보입니다.

```text
입력: 내일 오전 예약을 오후로 바꾸고 싶어요.

확인할 점
- 예약자명
- 현재 예약 시간
- 변경 가능한 오후 시간

답변 초안
안녕하세요. 예약 시간 변경을 도와드리겠습니다…
```

완성된 서비스 전체가 아니라도 **입력 하나가 출력 하나로 이어지는 첫 조각**이 생겼습니다.

### 장면 10 · AI가 “완료”라고 했지만 버튼이 안 눌립니다

모아는 작업이 끝났다고 말합니다. 그런데 민지가 다른 가상 문의를 넣고 버튼을 누르자 아무 일도 일어나지 않습니다.

민지는 원인을 모르기 때문에 해결책을 지어내지 않고 화면과 상황을 그대로 줍니다.

**민지**

```text
새 문의를 넣고 버튼을 눌렀는데 아무 일도 안 일어나.
지금 화면 스크린샷과 아래 오류 문구를 같이 봐줘.

[오류 문구를 그대로 붙여넣음]

무슨 뜻인지 먼저 쉬운 말로 설명해줘.
된 부분은 버리지 말고 가장 작은 변경으로 고친 뒤,
네가 직접 같은 샘플을 두 번 실행해줘.
```

**모아**

> 버튼 모양은 만들어졌지만 버튼을 눌렀을 때 결과를 바꾸는 연결이 빠져 있습니다. 이미 만든 화면은 두고 연결 부분만 고치겠습니다.

수정 뒤 모아가 검사 결과를 보여줍니다.

```text
첫 번째 샘플 실행: 통과
두 번째 샘플 실행: 통과
npm run build: 통과
npm run check: 통과
```

민지는 브라우저에서 직접 버튼을 두 번 눌러봅니다. **오류를 그대로 붙여넣기, 스크린샷 보여주기, 더 쉽게 설명해달라고 하기**가 이 장면에서 사용한 낙법입니다.

## 내 개념 페이지 · 헷갈린 말을 내 지식으로 바꾸기

### 장면 11 · “빌드가 뭐야?”를 그냥 넘기지 않습니다

작업 중 모아가 계속 말한 ‘빌드’가 무엇인지 민지는 아직 모릅니다.

**민지**

```text
`.claude/skills/개념정리/SKILL.md`를 읽고 진행해줘.
오늘 계속 나온 ‘빌드’가 아직 잘 이해되지 않아.

사전처럼 설명하지 말고 방금 만든 문의 답변 도구를 예로 들어서,
미리보기와 빌드가 어떻게 다른지 코딩 모르는 사람도 알게 설명해줘.
결과는 내 학습허브의 개념 위키 페이지 한 장으로 저장해줘.
```

모아는 민지의 프로젝트 화면과 검사 과정을 예로 설명한 개념 페이지를 만듭니다. 수업 중 다 읽지 못하더라도, 민지는 나중에 자기 예시로 다시 공부할 수 있습니다.

민지는 다른 사람들에게 코드나 전체 과정을 설명하려 하지 않습니다.

## AI 팀원 만들기 · 다음 대화에 인수인계하기

### 장면 13 · 지금까지 생긴 문서를 HANDOFF로 연결합니다

수업이 끝나갈 무렵 민지는 다음번 새 대화가 오늘 작업을 이어받을 수 있게 요청합니다.

**민지**

```text
오늘 만든 나에 대한 문서, 프로젝트 카드·미니 PRD·개념 페이지와
현재 결과물을 읽고 HANDOFF.md 한 장을 만들어줘.

담을 것:
- 이 프로젝트가 해결하려는 문제
- 지금 실제로 되는 것과 아직 안 되는 것
- 다음에 할 가장 작은 한 단계
- 네가 알아서 해도 되는 것과 반드시 나한테 물어볼 것
- 새 대화에서 먼저 읽을 원문 위치

없는 문서나 한 일을 지어내지 말고 실제로 생긴 것만 써줘.
```

HANDOFF가 생기자 민지는 또 새 대화를 열어 시험합니다.

**민지**

```text
AGENTS.md의 지침을 먼저 따르고 HANDOFF.md를 읽어줘.
지금 실제로 되는 것, 아직 안 되는 것,
다음에 할 가장 작은 한 단계를 알려줘.
```

**새 대화의 모아**

> 가상 예약 변경 문의를 넣어 확인할 점과 답변 초안을 만드는 흐름은 작동합니다. 실제 고객 데이터 연결과 자동 발송은 하지 않았습니다. 다음 한 단계는 민지님이 실제로 쓰는 말투 기준을 가상 예시로 정하는 것입니다.

학습메이트가 민지를 아는 파일, 기획 문서, 결과물, 개념 위키가 있었기 때문에 HANDOFF는 막연한 대화 요약이 아니라 **다음 AI가 확인할 원문 지도**가 됩니다.

## 결과 저장 · 비공개 GitHub에 올리기

### 장면 14 · 저장하기 전 개인정보부터 확인합니다

마지막으로 민지는 오늘 결과를 컴퓨터 안에만 두지 않기로 합니다.

**민지**

```text
오늘 만든 결과를 안전하게 저장할 거야.
먼저 `.claude/skills/올리기전점검/SKILL.md`를 읽고 점검해줘.

개인정보·비밀번호·API 키가 없고 저장소가 private인지 확인한 뒤,
오늘 변경을 한 커밋으로 만들고 내 GitHub 저장소에 push해줘.
브라우저 승인이 필요할 때만 알려줘.
```

AI가 점검하고 결과를 보고합니다.

```text
저장소 공개 범위: PRIVATE
실제 고객 정보·비밀번호·API 키: 발견되지 않음
커밋: 고객 문의 답변 첫 조각 완성
GitHub push: 완료
```

민지는 Git 명령어를 외우지 않았지만, **무엇을 시켰고 무엇을 직접 확인해야 하며 다음 작업이 어디서 이어지는지**는 설명할 수 있게 됐습니다.

## 이 흐름에서 민지가 반복한 일

민지는 AI에게 완벽한 지시를 한 번에 내리지 않았습니다.

1. 모르면 **“이걸 하려면 무엇이 필요해?”**라고 물었습니다.
2. 답을 들으면 **“그러면 네가 해줘”**라고 실행을 맡겼습니다.
3. 이해가 안 되면 **“더 쉽게 설명해줘”**라고 다시 물었습니다.
4. 오류가 나면 해결책을 추측하지 않고 **화면과 오류를 그대로 보여줬습니다.**
5. AI가 끝났다고 해도 **실제 화면·파일·검사 결과를 직접 확인했습니다.**
6. 중요한 대화는 프로젝트 카드·PRD·개념 위키·HANDOFF 같은 **문서로 남겼습니다.**

이것이 오늘 수업에서 반복해서 연습할 작업 방식입니다.
