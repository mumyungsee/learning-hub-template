민지는 코딩을 배운 적이 없는 고객 응대 담당자예요. 비슷한 문의에 매번 답변을 새로 쓰는 일이 지겨워서, 오늘 처음으로 AI와 작은 업무 도구를 만들어봐요.

이 페이지는 사용 설명서가 아니에요. **민지가 무엇을 말하고, AI가 어떻게 움직이고, 어디서 막히고, 무엇을 남기는지** 옆에서 한 바퀴 따라가는 이야기예요.

## 준비 · AI가 실제로 일할 자리 만들기

### 장면 1 · “명령어를 모르는데도 할 수 있나요?”

**민지**

> 고객 문의 답변 만드는 일을 줄이고 싶어요. 그런데 저는 코딩도 모르고 터미널 명령어도 몰라요.

**AI**

> 괜찮아요. 민지님은 원하는 결과를 말해주세요. 제가 `git`, `gh`, `npm` 같은 도구를 확인하고 필요한 명령을 직접 실행할게요. 로그인이나 설치 권한이 필요할 때만 민지님이 승인해주세요.

AI가 컴퓨터를 확인한 뒤 짧게 보고해요.

```text
git: 사용 가능
gh: 민지의 GitHub 계정으로 로그인됨
node·npm: 사용 가능
현재 작업 폴더: 확인됨
```

민지는 명령어를 외우지 않았어요. 대신 **목적은 사람이 정하고, AI는 CLI(명령줄 도구)를 손처럼 사용하며, 중요한 승인과 최종 확인은 사람이 한다**는 역할을 알게 돼요.

### 장면 2 · 포크하지 않고 내 프로젝트로 시작하기

**민지**

> 이 학습허브 템플릿으로 `my-learning-hub`라는 비공개 프로젝트를 만들어서 제 컴퓨터에 가져와주세요.

**AI**

> 원본에 기여하려는 것이 아니니 포크하지 않고, 템플릿으로 독립된 새 저장소를 만들게요. GitHub 로그인이 필요하면 브라우저를 열어드릴게요.

민지가 브라우저에서 로그인을 승인하자 AI가 `gh`를 이용해 저장소를 만들고 첫 화면까지 띄워요.

```text
GitHub 저장소: minji/my-learning-hub
공개 범위: PRIVATE
내 컴퓨터 폴더: my-learning-hub
첫 화면: http://localhost:4321
```

여기서 템플릿은 남의 작업을 계속 따라가는 복사본이 아니라 **내 프로젝트로 독립해서 출발하는 뼈대**예요. 민지는 AI의 “완료”라는 말 대신 비공개 여부·폴더·첫 화면을 직접 확인해요.

### 장면 3 · 새 대화도 나를 알게 하기

첫 화면은 열렸지만, AI는 아직 민지가 어떤 일을 하는지 몰라요.

**AI**

> 반복해서 귀찮은 업무가 무엇인가요?

**민지**

> 예약 변경이나 이용 문의가 반복돼요. 확인할 내용을 빠뜨리지 않으면서 답변 초안을 빨리 만들고 싶어요. 어려운 말은 쉽게 설명해주세요.

AI는 대화를 바탕으로 `SOUL.md`, `USER.md`, `AGENTS.md`를 만들어요. 민지가 같은 폴더에서 새 대화를 열어 물어봐요.

**민지**

> 제 이름과 제가 오늘 해결하려는 일을 알려주세요.

**새 대화의 AI**

> 민지님은 고객 응대 업무를 하고 있고, 반복 문의의 답변 초안을 더 안전하고 빠르게 만드는 일을 시작하려고 합니다.

대화가 바뀌었는데도 답이 이어졌어요. AI가 기억한 것이 아니라 **프로젝트 지침 파일을 다시 읽은 것**이에요.

## Plan · 오늘 만들 크기 정하기

### 장면 4 · 막연한 불편을 프로젝트 카드로 바꾸기

**민지**

> 고객 문의를 자동화하고 싶은데, 뭘 만들어야 할지는 잘 모르겠어요. 질문해서 같이 정해주세요.

AI는 “누가 쓰나요?”, “무엇을 넣으면 무엇이 나오면 좋나요?”, “실제 고객 정보 없이 시험할 수 있나요?”라고 하나씩 물어요. 대화가 끝나자 프로젝트 카드 한 장이 생겨요.

```text
문제: 반복 문의마다 답변을 처음부터 다시 쓴다
사용자: 고객 응대 담당자 민지
입력: 개인정보가 없는 가상 고객 문의
원하는 결과: 확인할 점 + 답변 초안
```

“업무 자동화”라는 큰 말이 **누구의 어떤 장면을 바꿀지 적은 프로젝트 카드**로 좁아졌어요.

### 장면 5 · AI가 너무 크게 잡은 계획을 줄이기

처음에 AI는 고객 데이터베이스, 자동 이메일 발송, 관리자 화면까지 제안해요.

**민지**

> 이걸 오늘 60분 안에 다 만들 수 있나요? 실제 고객에게 자동으로 보내는 기능은 무서워요.

**AI**

> 지금 범위는 너무 커요. 오늘은 가상 문의 하나를 넣으면 확인할 점과 답변 초안이 나오는 장면만 만들게요.

AI가 미니 PRD를 다시 써요.

```text
오늘 만들 것: 가상 문의 → 확인할 점 + 답변 초안
완료 확인: 브라우저에서 같은 샘플로 다시 실행해보기
오늘 만들지 않을 것: 로그인, 고객 DB, 자동 발송, 실제 개인정보
```

AI가 처음 내놓은 계획도 정답은 아니에요. **미니 PRD는 무엇을 만들지뿐 아니라 무엇을 만들지 않을지도 정하는 짧은 약속**이에요.

## Do · 작동하는 첫 조각 만들기

### 장면 6 · 한 번에 전부 말고, 되는 장면 하나

**민지**

> 프로젝트 카드와 미니 PRD를 읽고 시작해주세요. 한 번에 다 만들지 말고, 작은 단계마다 직접 확인해주세요.

AI가 먼저 가상 문의를 준비하고, 그다음 입력 칸과 결과 칸을 만들어요. 잠시 뒤 민지가 브라우저에서 시험해요.

```text
입력: “내일 예약 시간을 오후로 바꿀 수 있나요?”

확인할 점: 예약자명, 현재 예약 시간, 가능한 변경 시간
답변 초안: “안녕하세요. 예약 변경을 도와드리겠습니다…”
```

완성된 서비스는 아니지만, 처음부터 끝까지 한 번 작동해요. 이것이 **첫 조각(MVP)**이에요.

## Check · AI의 완료 보고도 직접 확인하기

### 장면 7 · “됐다고 했는데 버튼이 안 눌려요”

AI는 “완료했습니다”라고 말했지만 민지가 다시 눌러보니 결과가 나오지 않아요.

**민지**

> 버튼을 눌러도 아무 일도 안 일어나요. 지금 화면과 오류 문구를 보고, 된 부분은 지키면서 가장 작게 고쳐주세요. 고친 뒤 직접 다시 실행해주세요.

AI가 확인하니 버튼과 결과를 연결하는 부분이 빠져 있었어요. 그 부분만 고치고 같은 샘플을 두 번 실행한 뒤 빌드와 구조 검사 결과를 보여줘요.

```text
샘플 실행: 통과
두 번째 실행: 통과
build: 통과
check: 통과
```

AI는 자신 있게 틀릴 수 있어요. 이때 화면·오류·스크린샷을 그대로 보여주는 것이 낙법이고, **AI의 말이 아니라 실제 동작을 보는 것**이 검수예요.

## Act · 배운 것과 다음 일을 남기기

### 장면 8 · 헷갈린 말을 내 프로젝트의 지식으로 바꾸기

작업 중 민지는 AI가 계속 말한 “빌드”가 무엇인지 헷갈렸어요.

**민지**

> “빌드”가 무엇인지 방금 만든 문의 답변 도구를 예로 설명해주세요. 개념 위키 페이지로 남겨주세요.

AI는 “미리보기가 요리 중간에 맛을 보는 것이라면, 빌드는 손님에게 내놓을 한 상이 제대로 차려지는지 마지막으로 확인하는 것”이라고 민지의 결과물에 빗대어 설명해요.

이제 개념은 대화 속에서 사라지지 않고 **내가 다시 읽을 수 있는 위키 문서**가 돼요.

### 장면 9 · 다음 AI에게 인수인계하기

수업이 끝나갈 무렵 민지는 새 대화에서도 작업이 이어질지 시험해요.

**민지**

> 프로젝트 카드, 미니 PRD, 개념 페이지와 지금 결과물을 읽고 `HANDOFF.md`를 만들어주세요. 되는 것, 안 되는 것, 다음 한 단계를 적어주세요.

새 대화를 열어 `HANDOFF.md`를 읽히자 AI가 답해요.

**새 대화의 AI**

> 가상 문의를 넣어 답변 초안을 만드는 흐름은 작동합니다. 실제 고객 데이터 연결과 자동 발송은 아직 하지 않았습니다. 다음 한 단계는 답변 초안의 말투를 민지님 업무에 맞게 조정하는 것입니다.

이전 대화를 통째로 기억하지 않아도, **현재 상태와 원문 위치가 적힌 인수인계 문서**가 있으면 다음 AI가 이어받을 수 있어요.

### 장면 10 · 개인정보를 확인하고 저장하기

마지막으로 민지는 오늘 결과를 컴퓨터 안에만 두지 않기로 해요.

**민지**

> 실제 개인정보나 비밀번호가 없는지 확인하고, 저장소가 비공개인지 다시 본 뒤 오늘 변경을 저장해주세요.

AI가 점검한 뒤 보고해요.

```text
저장소 공개 범위: PRIVATE
개인정보·비밀키: 발견되지 않음
커밋: “고객 문의 답변 첫 조각 완성”
GitHub push: 완료
```

민지는 명령어를 외우지 않았지만, **무엇을 만들었고 어디에 저장됐으며 다음에 무엇을 할지**는 설명할 수 있어요. 이것이 AI와 일하는 방식이에요.

## 민지가 한 바퀴 돌며 만든 것

| 장면 | 민지가 한 행동 | 새로 이해한 것 | 손에 남은 것 |
|---|---|---|---|
| 1 | AI에게 도구 점검을 맡김 | CLI, 사람과 AI의 역할 | 준비된 컴퓨터 |
| 2 | 템플릿으로 비공개 프로젝트 생성 | 템플릿, 저장소 | 내 저장소와 첫 화면 |
| 3 | 학습메이트 인터뷰와 새 대화 확인 | 프로젝트 지침 | `SOUL.md`·`USER.md`·`AGENTS.md` |
| 4 | 업무 문제를 질문으로 좁힘 | 프로젝트 카드 | 문제·사용자·입출력 정의 |
| 5 | 너무 큰 계획을 60분 크기로 줄임 | 미니 PRD, 범위 | 완료 기준과 하지 않을 것 |
| 6 | 입력 → 출력 한 장면을 만듦 | 첫 조각(MVP) | 작동하는 결과물 |
| 7 | 오류를 보여주고 다시 실행함 | 낙법, 검수 | 재실행·빌드·검사 결과 |
| 8 | 헷갈린 말을 자기 예시로 정리함 | 개념 위키 | 개념 페이지 한 장 |
| 9 | 새 대화에 현재 상태를 넘김 | 인수인계 | `HANDOFF.md` |
| 10 | 비공개·개인정보 확인 뒤 저장함 | 커밋, 푸시 | 다시 꺼낼 GitHub 기록 |

**준비 → 계획 → 실행 → 확인 → 기록과 인수인계.** 민지는 이 흐름을 한 번에 완벽하게 끝낸 것이 아니라, 작게 계획하고(Plan), 만들고(Do), 확인하고(Check), 다음에 더 나아지게 남기는 것(Act)을 한 바퀴 돌았어요.

## 내 업무로 바꿔서 생각해보기

```text
위 민지의 이야기와 같은 순서로 내 업무 문제 하나를 다뤄보고 싶어.
내 상황을 지어내지 말고 질문을 한 번에 하나씩, 최대 세 개까지만 해줘.
답을 들은 뒤 민지의 4~10번 장면을 내 업무에 맞는 한 줄 시나리오로 바꿔줘.
아직 만들지는 말고 먼저 전체 흐름만 보여줘.
```
