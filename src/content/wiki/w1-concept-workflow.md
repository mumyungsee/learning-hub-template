이 페이지는 자세한 사용 설명서가 아니라 **처음 AI와 일할 때 어디로 가는지 보여주는 지도**예요. 한 번 읽고, 작업 중에는 “지금 몇 번째 장면이지?”만 확인하세요.

## 먼저 이해할 것 · AI에게 일을 맡긴다는 뜻

예전에는 사람이 터미널에 `git`, `gh`, `npm` 명령어를 하나씩 외워 입력해야 했어요. 이제는 **내가 원하는 결과를 말하면 AI가 필요한 명령어를 골라 직접 실행**할 수 있어요.

이때 CLI(명령줄 도구)는 글자로 프로그램을 조작하는 통로예요. AI가 생각만 하고 끝나지 않고 내 컴퓨터와 GitHub에서 실제로 일하게 해주는 **손**에 가까워요.

- **AI가 할 일** — 필요한 도구 확인, 명령 실행, 오류 해결, 결과 검증
- **내가 할 일** — 목적 정하기, 로그인·권한·외부 공개 승인하기, 결과가 맞는지 확인하기

명령어를 외울 필요는 없어요. 다만 AI의 “됐어요”를 그대로 믿지 않고 **무엇을 했고 무엇으로 성공을 확인했는지** 물어보는 것이 중요해요.

## 장면 1 · 일할 자리부터 준비해요

민지는 AI에게 바로 일을 시키지 않아요. GitHub 계정과 작업 도구를 준비하고, AI가 내 컴퓨터의 폴더를 읽고 파일을 고칠 수 있는지 먼저 확인해요. `git`은 파일 변경을 기록하고, `gh`는 GitHub 저장소를 다루고, `npm`은 사이트에 필요한 부품을 설치하고 실행해요. 이 도구가 있어야 AI가 말로만 설명하지 않고 실제 작업까지 할 수 있어요.

- **개념** — 로컬 폴더: 지금 내 컴퓨터에 있는 실제 작업 공간 · CLI: AI가 명령으로 도구를 움직이는 통로
- **남는 것** — 로그인과 설치가 끝난 준비된 컴퓨터

## 장면 2 · 빈 화면 대신 템플릿에서 시작해요

민지는 “학습허브 템플릿으로 내 비공개 프로젝트를 만들어줘”라고 목적을 말해요. AI는 `gh`를 사용해 **포크가 아닌 독립된 새 저장소**를 만들고 컴퓨터로 가져온 뒤 첫 화면을 띄워요. 포크는 원본 프로젝트에 기여할 때 쓰고, 템플릿은 내 프로젝트를 새로 시작할 때 써요.

- **개념** — 저장소(repository): 파일과 변경 기록을 함께 보관하는 프로젝트 상자 · 템플릿: 내 프로젝트로 독립해서 시작하는 출발점
- **확인** — 저장소가 비공개인지, 내 컴퓨터에 폴더가 생겼는지, 첫 화면이 열리는지
- **남는 것** — 내 저장소와 브라우저에 열린 첫 화면

## 장면 3 · 매번 나를 설명하지 않게 해요

민지는 AI와 짧게 인터뷰하고 `SOUL.md`, `USER.md`, `AGENTS.md`에 서로의 역할과 작업 규칙을 남겨요. 새 대화를 열어도 AI가 이 파일을 읽으면 같은 눈높이에서 다시 시작할 수 있어요.

- **개념** — 프로젝트 지침: AI가 작업 전에 읽는 공통 규칙
- **남는 것** — 나를 알고 안전 규칙을 지키는 학습메이트

## 장면 4 · 하고 싶은 일을 문제 한 줄로 좁혀요

민지는 “업무를 자동화하고 싶다”에서 멈추지 않고, 반복해서 불편한 장면 하나를 골라요. 왜 필요한지와 누구를 위한 것인지는 **프로젝트 카드**에 남겨요.

- **개념** — 프로젝트 카드: 문제·사용자·목적처럼 쉽게 바뀌지 않는 기준
- **남는 것** — 오늘 풀 업무 문제 한 가지

## 장면 5 · 오늘 끝낼 크기를 정해요

민지는 기능 목록을 늘리는 대신 “가상 문의 하나를 넣으면 답변 초안 하나가 나온다”처럼 입력과 출력을 한 장면으로 정해요. 완료 기준, 오늘 하지 않을 것, 할 일을 **미니 PRD** 한 문서에 적어요.

- **개념** — 미니 PRD: 무엇을 왜 만들고, 어디까지 되면 끝인지 적은 짧은 계획서
- **남는 것** — 완료 기준과 할 일이 들어간 실행 계획

## 장면 6 · 가장 작은 작동 장면을 만들어요

민지는 계획을 읽힌 뒤 한 번에 전부 만들지 않고, 작은 조각을 만들고 바로 확인해요. 오류가 나자 화면과 오류 문구를 그대로 AI에게 보여주고 “된 부분은 지키고 가장 작게 고쳐줘”라고 요청해요.

- **개념** — 첫 조각(MVP): 가치는 확인할 수 있지만 아직 작고 단순한 첫 결과물
- **낙법** — 화면 캡처, 오류 그대로 붙이기, 더 쉽게 설명 요청, 검색·공식 문서 확인
- **남는 것** — 같은 샘플로 다시 실행할 수 있는 입력 → 출력 한 장면

## 장면 7 · 낯선 말을 내 프로젝트의 지식으로 바꿔요

민지는 실습 중 자주 나왔지만 헷갈렸던 개념 하나를 골라요. AI는 사전식 설명이 아니라 방금 만든 프로젝트를 예로 들어 **개념 위키 페이지**로 남겨요.

- **개념** — 위키: 다음 대화와 다음 작업에서도 다시 꺼내 보는 지식 문서
- **남는 것** — 내 예시로 이해한 개념 페이지 한 장

## 장면 8 · 다음 AI가 이어받게 해요

민지는 대화 내용을 통째로 복사하지 않아요. 프로젝트 카드, 미니 PRD, 개념 페이지와 실제 결과물을 읽혀 `HANDOFF.md`를 만들어요. 새 대화에서 지금 되는 것과 다음 한 단계를 정확히 말하는지 확인해요.

- **개념** — 인수인계(HANDOFF): 현재 상태와 다음 행동을 알려주는 한 장짜리 안내서
- **남는 것** — 대화가 바뀌어도 이어서 일하는 AI 팀원

## 장면 9 · 안전하게 저장하고 다음 한 걸음을 남겨요

마지막으로 민지는 개인정보와 비밀번호가 섞이지 않았는지 확인하고, 결과를 비공개 GitHub 저장소에 올려요. 완벽한 서비스보다 **오늘 만든 것, 배운 것, 다음에 할 것**이 모두 다시 꺼내지는 상태가 오늘의 완성이에요.

- **개념** — 커밋·푸시: 변경을 한 묶음으로 기록하고 원격 저장소에 보관하는 과정
- **남는 것** — 내 저장소, 작동 결과물, 다음에 이어갈 한 단계

## 한눈에 보는 작업 흐름

**준비 → 템플릿 → 학습메이트 → 프로젝트 카드 → 미니 PRD → 첫 조각 → 개념 위키 → 인수인계 → 저장**

이 흐름은 한 번에 완벽하게 만드는 직선이 아니에요. 계획하고(Plan), 만들고(Do), 확인하고(Check), 고쳐서 다음에 남기는 것(Act)을 작게 반복하는 방식이에요.
