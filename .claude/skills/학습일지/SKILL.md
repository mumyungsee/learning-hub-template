# 학습일지 → 사례글

매일 챌린지 끝에 도는 루틴입니다. 오늘 배운 걸 정리하고(학습일지·비공개), 그중 자랑할 만한 걸 골라 사례글(공개)로 다듬습니다. 매일 하면 사이트가 저절로 채워지고, 4주 뒤 전자책이 됩니다.

> 주인이 **"오늘 학습일지 써줘"**라고 하면 아래 순서로 진행합니다.
> 5~10분이면 끝나게, **가볍게.** 매일 하는 거라 무거우면 안 됩니다.

---

## 진행 원칙 (제일 중요)

- **한 번에 하나씩** 묻습니다. 질문 여러 개를 한꺼번에 쏟지 않습니다.
- 매번 **먼저 제안**합니다. 주인이 짜내게 하지 말고, 오늘 대화를 보고 "오늘 이런 걸 한 것 같은데 맞아?"라고 먼저 짚어줍니다. 주인은 "응 / 조금 수정"만 하면 됩니다.
- 그냥 요약해버리지 않습니다. **물어서 주인이 답하는 과정 자체가 복습**입니다.
- 답이 얕으면 **딱 한 번만** 꼬리질문합니다.

---

## 0단계 — ★ 먼저 오늘 대화 기록을 찾아 읽는다 (이게 생생함의 핵심)

인터뷰 3개만으로 쓰면 글이 납작해집니다. **먼저 오늘 실제로 오간 작업 기록(세션 대화 로그)을 찾아 읽어**, 무엇을·어떤 프롬프트로·어디서 막혔는지 구체적으로 뽑습니다.

- **오늘 이 작업 세션의 대화 기록 파일을 찾아 읽습니다.** (환경마다 위치가 다르니 경로를 넘겨짚지 말고, 오늘 날짜의 세션 기록·로그 파일을 실제로 찾아서 읽습니다. 이 대화창 안에 이미 오늘 흐름이 다 있으면 그것도 재료입니다.)
- 거기서 **실제 오간 프롬프트·막힌 지점·해결 과정·전환점**을 뽑습니다. 이게 사례글을 두껍게 만드는 진짜 재료입니다.
- **못 찾으면** 아래 인터뷰로 진행합니다. (기록을 못 읽었으면 "지금은 이 대화 내용으로만 써서 좀 얕을 수 있어요, 더 자세한 기록이 있으면 알려주세요"라고 솔직히 알립니다.)

## 1단계 — 오늘 인터뷰 (기록으로 뽑은 걸 확인·보충, 3개 정도)

0단계에서 뽑은 걸 바탕으로, AI가 먼저 짚어주고 주인은 확인·보충만 합니다.

1. **오늘 뭐 했어?** — (AI가 기록에서 뽑아 먼저 제시, 주인은 "응/수정")
2. **막히거나 새로 알게 된 건?** — (기록의 막힘·전환점을 짚어줌)
3. **오늘 기분이나 느낌은?** — 뿌듯/답답/신기 등 한 줄. (학습일지는 나만 보니 솔직하게)

> 기록을 잘 읽었으면 인터뷰는 확인용이라 가볍습니다. 답이 얕으면 딱 한 번만 꼬리질문.

## 2단계 — 학습일지 저장 (비공개)

인터뷰 내용을 `src/content/journal/{오늘날짜}.md`에 저장합니다.

- **비공개**입니다. journal 폴더는 원래 사이트에 안 뜹니다. 날것·솔직해도 됩니다.
- 프론트매터: `title`(예: "7월 23일 학습일지"), `date`(오늘 날짜), `summary`(한 줄).
- 오늘 배운 개념·용어가 나왔으면 **학습일지 끝에 한 줄로 메모**합니다. (나중에 개념페이지 재료가 됩니다.)

## 3단계 — 사례글 소재 제시 (번호로)

학습일지에서 **남에게 보여줄 만한 글감**을 2~3개 뽑아 번호로 제시합니다.

- "오늘 중 사례글이 될 만한 건: 1) … 2) … 3) …"
- 각 소재는 "무엇을·어떻게 했나"가 담긴 것. (남이 따라 하거나 흥미로워할 것)
- 오늘 별거 없었으면 **"오늘은 사례글 없이 넘어가도 돼요"**라고 해도 됩니다. 매일 강제가 아니고, 되도록 하루에 하나면 됩니다.

## 4단계 — 사례글 작성 (선택, 공개)

주인이 번호를 고르면, 그 소재를 사례글로 다듬어 `src/content/wiki/`에 저장합니다.

- 프론트매터: `종류: 사례`, `주차`(지금 몇 주차인지), `title`, `date`, `공개: true`.
- 파일 이름은 **영문·숫자·하이픈**으로 (예: `w1-case-day3.md`). 한글 파일 이름은 주소가 깨집니다. 제목은 프론트매터 `title`에 한글로.
- ★ **개인정보·민감한 건 뺍니다.** 사례글은 공개 = 남이 봅니다.
- 되도록 하루에 사례글 하나.

### ★ 좋은 사례글 6기준 (이대로 쓴다 — 지피터스 베스트 선정 기준 분석)

납작한 글은 "오늘 이거 했다" 나열로 끝납니다. 아래 기준을 채우면 두껍고 따라 하고 싶은 글이 됩니다. **0단계에서 읽은 실제 기록**이 이 기준을 채우는 재료입니다.

1. **재현성 (제일 중요)** — 독자가 **보고 따라 할 수 있게.** 순서를 단계로, **실제 쓴 프롬프트를 그대로 인용**(복사해 쓸 수 있게), 필요하면 "이 화면에서 뭘 누른다"까지. (지피터스 심사에서 "이 사례 따라 할 수 있나"가 핵심 기준.)
2. **Before → After** — 뭐가 불편했고(공감) → 어떻게 바뀌었나. 가능하면 수치로(예: 1시간→5분).
3. **막힘 → 해결** — 중간에 막힌 것과 어떻게 뚫었는지. "나도 막혀도 되는구나" 안정감 + 배울 거리.
4. **솔직함·사람 냄새** — "낑낑댔다", 실패·삽질도 솔직히. 기술 과시 아니라 사람 이야기.
5. **재사용 자산** — 독자가 바로 가져다 쓸 것 하나(프롬프트 템플릿·체크리스트·배운 점 정리).
6. **구조·가독성** — 한 줄 요약 → (누구에게 도움) → 본문 → 마무리. 표·리스트로 숨 고르기. 비개발자도 이해되게 어려운 말 최소화.

- 기본 뼈대: **뭘·왜 했나(Before) → 어떻게(프롬프트 인용·막힘/해결) → 결과·느낀 점(After) → 배운 것/재사용 자산.** 나열 말고 스토리처럼.
- 스크린샷·이미지는 수강생이 직접 넣습니다(따라 하는 데 필요한 화면). AI는 "여기에 ○○ 화면 스크린샷을 넣으면 좋아요"라고 자리를 짚어줍니다.

---

## 왜 이렇게 (학습메이트가 알아둘 것)

- **학습일지 = 부엌(재료, 비공개) / 사례글 = 손님상(정제본, 공개).** 사례글만 위키·전자책에 쌓입니다. 학습일지는 재료라 안 올라갑니다.
- **매일 인터뷰가 곧 복습입니다.** 그냥 요약하면 안 흘려보내는 효과가 없습니다. 물어서 주인이 답하게 하는 게 핵심.
- **개인정보 필터**: 학습일지(비공개)는 솔직해도 되지만, 사례글(공개)로 다듬을 때 민감정보를 뺍니다.

## 짝 — 주간 종합 (수요일)

매일 사례글이 쌓이면, 매주 수요일에 `주간종합` 스킬(또는 "이번 주 회고일지랑 종합사례글 써줘")로 한 주를 묶습니다. 이 일일 루틴의 주간 버전입니다.
