# 내 학습허브 사이트

AI랑 함께 배우고 만든 것을 쌓는 나만의 사이트예요.
글(마크다운 `.md`)만 넣으면 사이트가 알아서 카드·목록을 만들어줘요. 레이아웃은 신경 안 써도 돼요.

> 💡 이 사이트를 도와줄 AI **학습메이트**는 1주차에 직접 만들어요. (공통 지침 파일 3종: `SOUL.md`·`USER.md`·`AGENTS.md` — Cowork·Codex 연결법은 별도 어댑터로 안내해요)

## 어디에 뭘 넣나요?

모든 글은 `src/content/` 안에 넣어요. 폴더 = 글의 종류예요.

| 폴더 | 무슨 글 | 사이트에 보이나? |
|------|---------|------------------|
| `src/content/landing/` | **랜딩** (홈 화면 내 소개 글, `landing.md` 하나) | 홈 화면 위쪽 |
| `src/content/wiki/` | **학습위키** (로드맵·계획·개념·사례·회고 다 여기) | 보임 (학습위키 메뉴) |
| `src/content/projects/` | 내 프로젝트 소개 | 보임 (프로젝트 메뉴) |
| `src/content/journal/` | 저널 (개인 학습일지) | **안 보임** (나만 봄) |

### 홈 화면(랜딩)은 어떻게?

홈 화면 위쪽은 `src/content/landing/landing.md`에 쓴 내 소개 글이 나와요. 그 아래는
프로젝트·학습위키 최근 글이 **자동으로** 딸려와요.

- **1주차에** 아이데이션·로드맵을 하고 나면, 그 대화 내용으로 `landing.md`를 채워요.
  (학습메이트한테 "이 대화로 내 랜딩페이지 글 만들어줘"라고 하면 편해요)
- 아직 안 만들었으면 홈은 "1주차에 여기를 채워요" 안내를 보여줘요. 지워도 사이트는 잘 나와요.

### 학습위키가 자동으로 정리되는 법

위키 글 맨 위에 `종류`와 `주차`만 적으면, 왼쪽 목록이 알아서 정리돼요.

- `종류: 로드맵` — 한 달 전체 지도. 맨 위 자리 (1주차에 하나)
- `종류: 계획` — 이번 주에 뭘 어디까지 만들지 (미니 PRD·실행 로드맵·완성 기준)
- `종류: 개념` — 그 주에 배울 개념
- `종류: 사례` — 매일 쓰는 사례글 (하루 하나씩 쌓임)
- `종류: 회고` — 그 주 종합 (주차 끝, 발표용)
- `주차: 1` ~ `4` — 몇 주차 글인지

그래서 좌측 위키가 **로드맵 → 1주차(계획·개념·사례·회고) → 2주차 …** 순으로 자라요.

> ★ **계획은 대화에 두지 말고 파일로.** 매일 새 대화로 시작하니까, 대화에만 있으면 다음 날 사라져요. 학습메이트가 알아서 챙기지만 알고는 있으면 좋아요.

### 공통 규칙

- ★ **파일 이름은 영문·숫자·하이픈으로!** (예: `w1-case-day1.md`) 한글 파일 이름은 주소에서 깨져요. 제목은 안에 `title`로 한글로 쓰면 돼요.
- 각 폴더에 **견본 파일이 하나씩** 들어있어요(`공개: false`라 사이트엔 안 보여요). 새 글은 이 견본을 복사해서 내용만 바꾸면 제일 쉬워요. 보통은 학습메이트가 알아서 만들어주니 직접 만질 일은 적어요.
- 맨 위 `---`로 감싼 부분만 채우면 돼요. 그 아래는 자유롭게 마크다운으로.
- 어떤 글이든 안 보이게 하려면 맨 위에 `공개: false`를 넣으면 돼요.
- 본문에서 어려운 용어엔 자동으로 설명 풍선(툴팁)이 뜨고, 코드 상자엔 복사 버튼이 생겨요.

## 내 사이트 이름 바꾸기

`src/config/site.ts` 파일 하나만 열어서 이름·인사말·소개를 내 걸로 바꾸면 사이트 전체에 반영돼요.

## 내 서재 — 프로젝트 하나가 책 한 권

프로젝트 하나가 책 한 권이 돼요. **책장에 낼지 말지는 내가 정해요.**

- 프로젝트 카드에 `책: true`를 넣으면 서재 책장에 꽂혀요. 다시 `false`로 내려도 되고요
- **꺼둬도 사례글은 그대로** 프로젝트 밑에 작업 기록으로 달려요. 글이 사라지는 게 아니에요
- 꺼둔 책도 주소는 살아 있어서 **나만 미리 읽어볼** 수 있어요
- 사례글에 `프로젝트: (카드 파일 이름)`을 달면 그 책에 한 꼭지씩 쌓여요
- 책 안에서도 주차가 챕터가 돼요
- 프로젝트에 안 매인 글(학습 로드맵·개념·주차 회고)은 서재 아래 **그 밖의 기록**에 모여요

> 💡 "몇 편 이상이면 자동으로 책" 같은 규칙은 일부러 안 넣었어요. 글 한두 개로 책이 나오면 민망하잖아요. **낼 때를 정하는 건 나예요.**

> 💡 글은 언제나 `src/content/wiki/` 한 곳에만 살아요. **서재는 그 글을 프로젝트별로 다시 꿴 것**뿐이에요. 위키로 봐도 되고 책으로 봐도 되는, 같은 글의 다른 모습이에요.

## 딸려오는 도구들 (스킬)

이 템플릿에는 **자주 하는 일의 순서를 미리 적어둔 설명서**가 들어 있어요. 학습메이트한테 아래처럼 말하면 그대로 진행해요.

| 이렇게 말하면 | 하는 일 | 언제 |
|---|---|---|
| "내 프로젝트를 찾고 싶어" | 인터뷰로 만들 것을 찾고 프로젝트 카드까지 | 1주차 한 번 |
| "내 4주 학습 로드맵 만들어줘" | 뭘 배우고 어떻게 기록할지 지도 + 랜딩 소개글 | 1주차 한 번 |
| "오늘 학습일지 작성해줘" | 학습일지(비공개) → 사례글(공개) | 매일 |
| "이번 주 회고일지랑 종합사례글 써줘" | 한 주 재료를 모아 회고와 발표용 글 | 주 1회 |
| "이 사례 따라 하고 싶어" | 사례글을 따라 할 단계로 풀고 개념 정리 | 필요할 때 |
| "방금 물어본 것들 개념 페이지로 정리해줘" | 물어본 것들을 위키에 개념페이지로 | 필요할 때 |
| "미니 PRD 만들어줘"·"실행 로드맵 만들어줘"·"완성 기준 정하자" | 이번 주에 뭘 어디까지 만들지 정해 **위키에 파일로** | 주차마다 한 번 |
| "올리기 전에 점검해줘" | 개인정보·비밀키가 섞였는지 **전수 검사** | 배포·push 전마다 |
| "이거 가져와도 돼?" | 외부 소스의 안전성·요구 권한·라이선스 확인 | 남의 것을 받기 전 |
| "사이트에 ○○ 추가해줘" | 구조를 안 무너뜨리며 화면·기능 고치기 | 사이트를 손댈 때 |

원본은 `.claude/skills/` 안에 있어요. 열어봐도 되고, 4주차쯤엔 **내가 자주 시키는 일을 스킬로 직접 만들** 수도 있어요.

> 💡 도구마다 스킬을 부르는 방법이 조금 달라요. 슬래시 명령이 안 되면 그냥 위 문장을 말하면 학습메이트가 설명서를 읽고 진행해요.

## AI와 새 기능을 만들 때

처음부터 완벽한 설계를 할 필요는 없어요. 대신 기능을 더 붙여도 쉽게 무너지지 않는
**확장 가능한 최소 구조**만 지켜요.

- 화면, 콘텐츠·데이터, 재사용 요소를 한 파일에 몰아넣지 않아요. 이 템플릿처럼 페이지(`pages`), 글과 데이터(`content`·`config`), 재사용 요소(`components`) 정도만 구분해요.
- 카드·버튼·목록처럼 반복되는 모양은 재사용 가능한 단위로 만들고, 반복되는 링크·문구·이미지 주소는 한 곳에서 관리해요.
- 새 기능을 붙이기 전 지금 잘 되는 화면을 먼저 확인하고, 붙인 뒤 같은 화면과 기능이 깨지지 않았는지 다시 확인해요.
- 막히면 통째로 다시 만들지 말고 현재 구조를 먼저 읽은 뒤 가장 작은 변경으로 붙여요.
- 지금 MVP에 실제로 필요한 만큼만 나눠요. 과도한 추상화보다 작동하는 결과물 완성이 먼저예요.

## 사이트 미리 보기 / 배포

```bash
npm install     # 처음 한 번만 (필요한 부품 설치)
npm run dev      # 내 컴퓨터에서 미리보기 (http://localhost:4321)
npm run build    # 배포 전 이상 없는지 검사
npm run check    # 사이트를 고친 뒤 구조가 안 무너졌는지 검사
```

> 💡 **사이트를 고쳤으면 `npm run check`를 한 번 돌려보세요.** 화면은 멀쩡해 보여도 나중에 문제가 될 것들(같은 값이 두 군데로 갈라졌다든지)을 미리 잡아줘요. 무슨 말인지 모르겠으면 학습메이트한테 결과를 보여주면 돼요.

### 내 AX 구조 지도 보기

처음 설치를 끝낸 뒤 Windows에서는 `open-workspace-map.cmd`를 한 번 실행하세요. 다른 환경에서는 `npm run map`을 실행하면 돼요. 같은 지도 안에서 처음부터 들어 있던 파일은 **기본 제공**, 지금 선택한 업무를 위해 만든 파일은 **이번 업무**로 나뉘어 보여요.

- 지도는 파일을 **읽어서 상태만 보여주며 수정하거나 실행하지 않아요.**
- 파일 내용·절대경로·환경변수·`.git` 정보는 화면에 내보내지 않고, 지원되는 상대경로와 상태만 보여줘요.
- 각자 자기 템플릿 폴더에서 실행하므로 다른 사람 PC가 아니라 지금 실행한 폴더의 파일만 보여줘요.
- 로컬 미리보기에서만 상태가 자동 갱신돼요. 서버 연결이 끊기면 마지막 화면을 남기되 `업데이트 중단`이라고 분명히 표시해요.
- 지도 전용 검사는 `npm run check:map`으로 실행해요.

이번에 위임할 업무를 정한 뒤 학습메이트에게 이렇게 말하면 돼요.

> “이 업무를 AX 구조 지도의 이번 업무로 연결해줘. 새 파일을 만들 때마다 지도 포인터도 갱신해줘.”

학습메이트는 `.workspace-map/active-work.json`에 업무 이름과 실제 상대경로만 기록해요. 원본 파일을 복사하거나 옮기지 않으며, 이 파일이 아직 없으면 지도에는 “이번에 위임할 업무는 아직 연결되지 않았어요”라고 나오는 것이 정상이에요.
