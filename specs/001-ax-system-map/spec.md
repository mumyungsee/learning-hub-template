# Feature Specification: 실습용 AX 구조 지도

**Feature Branch**: `N/A (specification only; no branch created)`

**Created**: 2026-09-03

**Status**: Draft

**Input**: User description: "수강생용 템플릿의 기본 위임 구조를 구조도로 보여주고, 실습 중 명세·계획·작업·스킬·스크립트·검증·인계 문서가 추가되거나 바뀌면 현재 상태와 연결 관계가 지도에 자동으로 반영되게 한다. 기업 후속 AX 강의에서 먼저 사용하고, 이후 AX 강의 모듈로 재사용한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 템플릿 구조 이해하기 (Priority: P1)

수강생은 실습을 시작하기 전에 구조 지도를 열어 `AGENTS.md`, `SOUL.md`, `USER.md` 같은 기본 지침과 도구별 진입점, 명세 문서, 스킬, 스크립트, 결과물, 검증 자료, `HANDOFF.md`가 각각 어떤 역할을 하며 어떤 흐름으로 연결되는지 한눈에 이해한다.

**Why this priority**: 구조를 이해하지 못하면 수강생이 파일 이름과 절차를 외우는 데 그치고, 자신의 업무에 맞게 위임 환경을 바꾸거나 재사용하기 어렵다.

**Independent Test**: 기본 템플릿만 있는 상태에서 지도를 처음 본 수강생이 주요 구성요소의 역할과 전체 위임 흐름을 지도만 보고 설명할 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기본 수강생 템플릿이 준비되어 있고, **When** 수강생이 구조 지도를 열면, **Then** 기본 지침·도구 진입점·작업 명세·실행 도구·검증·결과·인계의 구성요소와 순환 연결이 하나의 고정된 상세 구조도에 함께 보이며, 아직 없는 지식 관리는 선택 확장으로 구분된다.
2. **Given** 템플릿에는 `AGENTS.md`, `SOUL.md`, `USER.md`, `CLAUDE.md`, `GEMINI.md`와 기본 명세·결과·인계 흐름이 이미 있고, **When** 지도가 현재 상태를 표시하면, **Then** 이 파일을 별도 신규 노드로 복제하지 않고 `도구별 입구 → 공통 지침·맥락 → 명세`의 실제 읽기 순서와 함께 대응하는 고정 노드의 상세에서 보여준다.
3. **Given** 이번에 위임할 업무를 아직 선택하거나 연결하지 않았고, **When** 지도가 열리면, **Then** 템플릿 고정 구조만 보이고 “이번에 위임할 업무는 아직 연결되지 않았어요.”라는 뜻을 분명히 보여준다.
4. **Given** 템플릿 구조와 수강생이 추가한 구성요소가 모두 지도에 있고, **When** 수강생이 지도를 처음 보면, **Then** 별도 트랙을 오가지 않고 하나의 구조 안에서 어느 노드가 고정된 자리이고 무엇이 새로 붙은 구성요소인지 구분할 수 있다.

### User Story 2 - 실습 진행 상태를 지도에서 확인하기 (Priority: P2)

수강생과 강사는 실습 중 명세·계획·작업 목록, 스킬, 스크립트, 도구 연결, 결과물, 검증 자료, 인계 문서가 생성·변경·이동·삭제되는 상황을 지도에서 확인한다. 이를 통해 지금 위임 흐름의 어느 부분을 만들고 있고 다음에 무엇이 필요한지 파악한다.

**Why this priority**: 실습 결과가 실제 구조에 어떻게 연결되는지 바로 확인해야 AX 위임 시스템을 단순 문서 작성이 아니라 작동하는 하나의 흐름으로 이해할 수 있다.

**Independent Test**: 지원 대상 구성요소를 하나씩 생성·변경·이동·삭제하고, 별도의 지도 편집 없이 상태와 연결 관계가 정확히 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 구조 지도가 열린 실습 환경에서 이번 업무가 연결되어 있고, **When** 수강생이 명세·결과·인계 같은 기본 흐름의 파일을 만들면, **Then** 5초 이내에 대응하는 고정 노드의 상태와 상세가 갱신되며 별도 중복 노드는 생기지 않는다.
2. **Given** 수강생이 업무 전용 스킬·스크립트·MCP 같은 실행 확장을 만들거나 연결하고, **When** 지도가 갱신되면, **Then** 그 확장만 하네스 기반 주변의 별도 사용자 노드로 나타난다.
3. **Given** 하나의 구성요소가 여러 파일로 이루어지고, **When** 수강생이 그 노드에 마우스를 올리거나 선택하면, **Then** 지도 본문을 복잡하게 만들지 않으면서 연결된 상대경로와 근거를 확인할 수 있다.
4. **Given** 자동 갱신이 일시적으로 불가능하고, **When** 수강생이 지도를 보고 있으면, **Then** 오래된 상태를 최신 상태처럼 보여주지 않고 갱신 실패와 마지막 확인 시점을 알 수 있다.
5. **Given** 지원 범위 밖의 위치에 파일이 추가되고, **When** 지도가 갱신되면, **Then** 그 파일을 현재 실습 구조의 일부로 잘못 표시하지 않는다.

---

### User Story 3 - 증거에 따라 완료 상태 판단하기 (Priority: P3)

수강생과 강사는 지도에서 각 구성요소가 단순히 존재하는지, 검증 근거까지 갖췄는지, 확인이 필요한지를 구분한다. 파일이 있다는 이유만으로 위임 환경이 완성되었다고 오해하지 않는다.

**Why this priority**: AX 위임에서 중요한 것은 파일 개수가 아니라 명세한 결과가 실제로 작동하고 검증되었는지이므로, 지도도 그 차이를 정직하게 보여줘야 한다.

**Independent Test**: 파일만 있는 상태와 명시적인 검증 근거가 연결된 상태를 각각 준비해 상태 표시가 다르게 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이번 업무 파일은 존재하지만 그 업무와 연결된 검증 근거가 없고, **When** 지도가 상태를 판정하면, **Then** ‘작업 중’과 ‘검증됨’을 구분하고 검증 완료로 표시하지 않는다.
2. **Given** 결과물과 인정 가능한 검증 근거가 연결되어 있고, **When** 지도가 갱신되면, **Then** 해당 요소와 검증의 연결 및 검증 상태를 보여준다.
3. **Given** 파일이나 상태를 해석할 수 없고, **When** 지도가 갱신되면, **Then** 추측으로 완료 처리하지 않고 ‘확인 필요’ 또는 동등한 상태와 이유를 보여준다.

---

### User Story 4 - 다른 AX 강의에서 재사용하기 (Priority: P4)

강사는 특정 고객 전용 문구나 경로를 걷어내는 별도 재작업 없이 기본 구조 지도와 실습 흐름을 다른 AX 강의의 재사용 가능한 커리큘럼 모듈로 조합할 수 있다.

**Why this priority**: 이번 수업만을 위한 일회성 자료가 아니라, 앞으로 반복되는 AX 수업에서 같은 핵심 개념과 실습 구조를 안정적으로 활용해야 한다.

**Independent Test**: 고객명과 수업명을 바꾼 새 수업 구성에서 기본 템플릿 지도를 열고, 이전 고객의 고유 정보 없이 동일한 핵심 구조와 진행 상태를 확인한다.

**Acceptance Scenarios**:

1. **Given** 동일한 수강생 템플릿을 사용하는 다른 AX 강의가 있고, **When** 강사가 구조 지도 모듈을 포함하면, **Then** 특정 고객의 고유 정보 없이 기본 구조와 실습 상태가 표시된다.
2. **Given** 강의마다 일부 선택 구성요소가 다르고, **When** 지도를 재사용하면, **Then** 없는 선택 요소를 시스템 오류로 오인하지 않으면서 실제 구성만 보여준다.

### Edge Cases

- `AGENTS.md`, `SOUL.md`, `USER.md` 중 일부가 없거나 이름만 비슷한 파일이 있을 때 실제 상태와 예상 상태를 구분한다.
- 같은 이름의 스킬이나 스크립트가 여러 지원 위치에 있을 때 각각의 실제 위치를 구분하고 임의로 하나로 합치지 않는다.
- 명세·계획·작업 문서가 생성되었지만 비어 있거나 읽을 수 없을 때 ‘완료’로 표시하지 않는다.
- 검증 결과가 오래되었거나 현재 결과물과 연결되지 않을 때 최신 검증으로 간주하지 않는다.
- 지원 대상 파일이 이름 변경·이동·삭제된 뒤 이전 항목이 지도에 남아 있는 고아 상태를 만들지 않는다.
- 실습 환경이 실행되지 않았거나 지도 갱신이 중단되었을 때 정적인 예시와 실제 현재 상태를 혼동하지 않게 한다.
- 파일 경로나 이름에 한글, 공백 또는 특수문자가 포함되어도 읽을 수 있는 항목은 누락하지 않으며, 읽을 수 없으면 이유를 표시한다.
- 연결 관계가 너무 많아졌을 때도 핵심 위임 흐름과 현재 작업 위치를 판독할 수 있어야 한다.
- 한 논리적 구성요소에 파일이 많아져도 지도 노드 안에 긴 목록이나 내부 스크롤을 만들지 않고, 상세 정보에서 전체 경로를 확인할 수 있어야 한다.
- 같은 파일이 여러 역할에 연결되거나 한 구성요소가 여러 고정 기반을 사용할 때는 중복 노드를 무분별하게 만들지 않고 관계를 명확히 보여줘야 한다.
- 한 고정 노드에 업무 전용 확장이 늘어날 때는 그 고정 노드 주변의 가지 영역이 먼저 확장되고, 공간이 부족할 때만 전체 캔버스가 확장되어야 한다.
- 기본 흐름에 이미 포함된 명세·검증·결과물·인계와 공통 지침 파일은 존재하더라도 별도 사용자 노드로 중복 표시하지 않아야 한다.
- 아직 연결하지 않은 DB·PKM 같은 선택 요소는 구현 완료로 보이지 않도록 ‘나중에 추가 가능’ 예시와 실제 추가 노드를 구분해야 한다.

## Requirements *(mandatory)*

### Scope Boundaries

- 이 기능은 수강생용 학습 템플릿과 그 안에서 진행되는 실습 범위만 보여준다.
- 대표의 실제 컴퓨터 전체, 회사 전체 업무 시스템, 외부 저장소를 자동 진단하는 기능은 포함하지 않는다.
- 지도를 통해 파일을 수정하거나 자동화를 실행하는 기능은 이번 범위에 포함하지 않는다.
- 로그인, 원격 동기화, 공개 배포, 기업별 접근 제어는 이번 범위에 포함하지 않는다.
- 아루나 사이트의 콘텐츠 저장·발행 구조 변경은 이번 범위에 포함하지 않는다.

### Functional Requirements

- **FR-001**: 지도는 기본 지침, 사용자 맥락, 도구별 진입점, 명세와 계획, 실행 구성요소, 결과물, 검증 근거, 인계 문서의 역할과 전체 순환 연결을 하나의 고정된 구조도에 보여줘야 한다. 아직 구현하지 않은 지식 관리는 선택 확장으로만 보여줘야 한다.
- **FR-002**: 지도는 템플릿의 고정 흐름을 한 번만 보여주고, 수강생이 만든 업무 전용 실행 확장만 대응하는 고정 노드 주변에 붙여야 한다. 기본 흐름과 확장을 별도 트랙이나 별도 큰 구획으로 나누지 않아야 한다.
- **FR-003**: 지도는 각 구성요소의 표시 이름, 역할, 이번 업무 기준 현재 상태, 연결된 고정 기반, 직접 연결된 앞뒤 요소를 지도 본문에서 확인할 수 있게 해야 한다.
- **FR-004**: 지도는 최소한 `AGENTS.md`, `SOUL.md`, `USER.md`, 도구별 지침 진입점, 명세·계획·작업 문서, 스킬, 스크립트, 도구 연결, 결과물, 검증 자료, `HANDOFF.md`를 지원 대상 유형으로 다뤄야 한다.
- **FR-005**: 지도는 지원 대상 구성요소의 생성·변경·이름 변경·이동·삭제를 별도 지도 편집 없이 현재 상태에 반영해야 한다.
- **FR-006**: 열린 실습 중의 변경은 변경 발생 후 5초 이내에 지도에 반영되어야 한다.
- **FR-007**: 자동 갱신이 실패하면 지도는 실패 사실, 마지막으로 정상 확인한 시점, 사용자가 취할 수 있는 간단한 재확인 방법을 보여줘야 한다.
- **FR-008**: 지도는 이번 업무 기준으로 ‘업무 미연결’, ‘작업 중’, ‘검증됨’, ‘확인 필요’를 시각적으로 구분해야 한다. 기본 제공 파일 수는 이 상태를 올리지 않는다.
- **FR-009**: ‘검증됨’ 상태는 현재 업무 포인터에 연결된 결과물과 명시적인 검증 근거가 있을 때만 표시해야 한다. 템플릿의 예시·체크리스트는 근거가 될 수 없다.
- **FR-010**: 해석할 수 없는 파일이나 관계는 임의로 추정하지 않고 ‘확인 필요’와 그 이유를 표시해야 한다.
- **FR-011**: 지도는 최근 추가·변경된 업무 전용 확장 노드 또는 기본 흐름의 변경된 고정 노드를 구분하여 수강생이 지금 작업 중인 위치를 찾을 수 있게 해야 한다.
- **FR-012**: 지도는 탭이나 별도 화면으로 핵심 구조를 나누지 않고 전체 연결을 항상 유지하며, 같은 화면에서 개별 구성요소의 상세 정보를 확인할 수 있게 해야 한다.
- **FR-013**: 지도는 1920×1080 화면의 일반 브라우저 100% 배율에서 주요 흐름과 핵심 글자를 읽을 수 있어야 한다.
- **FR-014**: 수강생은 별도의 시각화 도구를 직접 설치하거나 계정을 만들지 않고 준비된 학습 템플릿에서 지도를 사용할 수 있어야 한다.
- **FR-015**: 상태 확인 범위는 현재 학습 템플릿 아래의 사전에 정한 위치로 제한해야 하며, 컴퓨터의 다른 폴더를 탐색하지 않아야 한다.
- **FR-016**: 지도는 실습 파일의 내용을 외부로 전송하거나 원격 서비스에 저장하지 않아야 한다.
- **FR-017**: 지도 기능은 읽기 전용이어야 하며, 상태 확인 과정에서 수강생 파일을 생성·수정·이동·삭제하지 않아야 한다.
- **FR-018**: 재사용 가능한 기본 지도와 안내 문구에는 특정 고객만을 위한 이름·경로·업무 내용이 포함되지 않아야 한다.
- **FR-019**: 강사는 동일한 기본 지도를 다른 AX 강의 구성에 포함해도 핵심 구조와 상태 판정 규칙을 그대로 사용할 수 있어야 한다.
- **FR-020**: 지도는 사람의 업무, 도구별 입구, 공통 맥락, 명세, 실행 하네스, 검증, 결과, 인계를 모두 동시에 표시하고 새 세션 재진입 연결도 숨기지 않아야 한다. 지식 재사용은 PKM이 실제 연결된 뒤에만 실제 확장 노드로 표시한다.
- **FR-021**: 업무 전용 스킬·스크립트·MCP·API·DB·PKM 연계처럼 기본 흐름 밖에서 추가한 실행 확장은 별도의 지도 편집 없이 논리적 단위별 사용자 노드로 나타나야 하며, 확장이 삭제되거나 지원 범위를 벗어나면 해당 노드도 사라져야 한다.
- **FR-022**: 수강생은 별도 시각화 도구 설치 없이 각자의 템플릿 폴더에서 한 번의 전용 실행 동작으로 로컬 구조 지도를 열 수 있어야 한다.
- **FR-023**: 현재 위임 업무는 프로젝트 안의 작은 포인터 문서 하나가 업무 이름과 구성요소별 원본 위치를 가리키는 방식으로 연결해야 하며, 원본을 지도용 위치에 복사하지 않아야 한다.
- **FR-024**: 이번 업무 포인터가 없으면 지도는 기본 환경의 존재와 업무 미연결 상태를 동시에 알려야 하며, 생성 시각이나 최근 수정 시각만으로 업무 소속을 추정하지 않아야 한다.
- **FR-025**: 잘못된 구성요소 ID, 프로젝트 밖 경로, 환경 파일, 심볼릭 링크 또는 존재하지 않는 경로를 포인터가 가리키면 외부를 탐색하거나 완료로 처리하지 않고 확인 필요 이유를 보여줘야 한다.
- **FR-026**: 하나의 사용자 노드는 하나의 업무 전용 확장을 나타내며, 필요한 경우 여러 원본 파일을 가리킬 수 있어야 한다. 기본 명세·검증·결과·인계 파일은 이 규칙으로 새 노드를 만들지 않는다.
- **FR-027**: 사용자 확장 노드는 자신이 사용하는 템플릿 고정 노드 주변에 가지처럼 배치되고 그 고정 노드와 연결되어야 한다. 확장 노드끼리 별도의 두 번째 업무 흐름을 만들지 않아야 한다.
- **FR-028**: 지도 본문의 노드 안에는 긴 파일 목록이나 내부 스크롤을 두지 않아야 한다. 상대경로와 검증 근거는 마우스를 올렸을 때의 간단 정보와 선택했을 때의 상세 정보에서 확인할 수 있어야 한다.
- **FR-029**: 사용자 노드가 늘어나면 해당 고정 노드 주변의 가지 배치를 확장하고, 그래도 부족할 때 전체 캔버스를 확장해야 한다. 기존 노드나 글자가 겹치지 않아야 한다.
- **FR-030**: 실제 상태 수집 방식과 연결 형식을 변경하기 전에, 고정 구조에 사용자 노드가 직접 붙어 있는 통합 정적 시안을 별도 화면에서 검토하고 승인할 수 있어야 한다.
- **FR-031**: `CLAUDE.md`와 `GEMINI.md`처럼 공통 지침을 불러오는 도구별 연결 파일, 공통 규칙인 `AGENTS.md`, 사용자·말투 맥락인 `USER.md`와 `SOUL.md`의 실제 참조 관계는 고정 흐름의 상세에서 확인할 수 있어야 하며 신규 업무 노드로 중복 표현하지 않아야 한다.
- **FR-032**: DB·PKM처럼 아직 연결하지 않은 선택 요소를 예시로 보여줄 때는 실제로 추가된 업무 확장과 다른 모양·상태 문구를 사용하고 완료 상태 계산에서 제외해야 한다.
- **FR-033**: 도구별 입구는 공통 지침·맥락을 거쳐 명세로 이어져야 하며 입구에서 명세로 바로 건너뛰는 연결을 기본 흐름으로 표시하지 않아야 한다.
- **FR-034**: PKM은 결과물을 정제·저장하는 입력 연결과 다음 업무의 공통 지침·맥락으로 관련 지식을 돌려주는 재사용 연결을 모두 보여줘야 한다. 아직 PKM이 없으면 두 연결도 선택 예시 상태여야 한다.

### Key Entities

- **템플릿 고정 노드**: 공통 지침, 도구별 입구, 명세 방식, 하네스 기반, 검증 방식, 결과, 인계가 어디에 연결되는지를 알려주는 변하지 않는 자리다. 원본 배포 템플릿에 해당 실제 파일이 아직 없더라도 자리는 유지된다.
- **현재 업무 포인터**: 이번에 위임할 업무의 이름과 그 업무가 실제로 만든 파일들의 구성요소별 상대경로를 연결하는 작은 정본 파일이다.
- **사용자 확장 노드**: 수강생이 현재 업무를 위해 기본 흐름에 새로 붙인 실행 능력이다. 업무 전용 스킬, 스크립트, MCP, API, DB 또는 PKM 연계가 될 수 있으며 여러 파일을 가리킬 수 있다.
- **연결 관계**: 한 구성요소가 다른 구성요소를 참조·사용·생성·검증·인계하는 관계. 관계의 방향과 의미를 가진다.
- **상태 판정**: 구성요소가 아직 없음, 존재함, 검증됨, 확인 필요 중 어디에 해당하는지와 그 판단 근거를 나타낸다.
- **실습 범위**: 현재 지도에서 상태 확인을 허용한 학습 템플릿 내부 위치와 지원 대상 유형의 경계다.
- **검증 근거**: 결과가 요구사항에 맞게 작동했음을 확인하는 기록이며, 어떤 결과물과 언제 연결되었는지를 포함한다.
- **지도 스냅샷**: 마지막 정상 확인 시점의 구성요소·연결·상태 집합으로, 갱신 실패 시 오래된 정보임을 판별하는 기준이 된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 이번 업무가 연결되지 않은 템플릿에서는 고정 구조만 보이고, 템플릿 파일의 존재를 ‘이번 업무가 구현됨’ 또는 ‘작업 중’으로 오판하지 않는다.
- **SC-002**: 생성·변경·이름 변경·이동·삭제를 포함한 대표 변화 시나리오 10건 모두가 별도 지도 편집 없이 5초 이내에 올바르게 반영된다.
- **SC-003**: 현재 업무 포인터에 연결되지 않은 템플릿 파일과 검증 근거 없는 이번 업무 파일 100%가 ‘검증됨’으로 잘못 표시되지 않는다.
- **SC-004**: 처음 지도를 본 수강생이 10분 이내에 기본 지침에서 명세, 실행, 검증, 인계로 이어지는 흐름과 주요 구성요소 5개 이상의 역할을 설명할 수 있다.
- **SC-005**: 1920×1080 화면과 브라우저 100% 배율에서 별도 확대 없이 모든 핵심 단계명, 상태, 연결 설명을 읽을 수 있다.
- **SC-006**: 갱신 중단 시나리오에서 5초 이내에 최신 상태가 아님을 표시하며, 마지막 정상 확인 시점이 실제 기록과 일치한다.
- **SC-007**: 지원 범위 밖에 둔 대표 파일 10건 중 어느 것도 실습 구조의 구성요소로 표시되지 않는다.
- **SC-008**: 동일한 모듈을 다른 AX 강의 구성에 넣었을 때 특정 고객 정보가 0건 노출되고, 기본 흐름과 상태 확인 기능은 그대로 사용할 수 있다.
- **SC-009**: 상태 확인 전후에 실습 파일의 내용·이름·위치·수정 시각이 의도치 않게 바뀐 사례가 0건이다.
- **SC-010**: 명세·스킬·스크립트·검증·인계를 각각 하나씩 추가하는 대표 실습에서, 명세·검증·인계는 대응하는 고정 노드가 갱신되고 스킬·스크립트만 5초 안에 별도 확장 노드로 나타나 하네스 기반에 연결된다.
- **SC-011**: 1920×1080 화면에서 여덟 개 기본 흐름 노드, 새 세션 재진입과 업무 전용 확장 연결을 한 화면 흐름으로 판독할 수 있으며 PKM은 선택 예시로 구분된다.
- **SC-012**: 새 템플릿 복사본에서 전용 지도 실행 동작을 한 번 수행하면 브라우저에 그 복사본의 구조 지도가 열리고, 다른 PC나 원격 서비스의 파일을 참조하지 않는다.
- **SC-013**: 유효한 현재 업무에 명세·스킬·결과 구성요소를 각각 하나씩 연결하면 5초 안에 명세·결과 고정 노드의 상세가 갱신되고 스킬만 독립된 사용자 확장 노드로 나타난다.
- **SC-014**: 현재 업무가 없는 템플릿에서는 업무 제목 대신 업무 미연결 안내가 보이고, 고정 노드와 선택 예시가 있어도 실제 사용자 확장 수는 0개로 유지된다.
- **SC-015**: 처음 지도를 본 수강생 5명 중 4명 이상이 클릭하지 않고도 업무 전용 스킬·스크립트·MCP가 새로 붙은 확장이고 DB·PKM은 아직 연결하지 않은 선택 예시라는 점을 2분 안에 구분할 수 있다.
- **SC-017**: 처음 지도를 본 수강생 5명 중 4명 이상이 고정 노드의 상세를 열어 `CLAUDE.md`·`GEMINI.md`가 `AGENTS.md`를 가리키고, `AGENTS.md`가 `SOUL.md`·`USER.md`와 스킬 사용 규칙을 연결한다는 흐름을 3분 안에 설명할 수 있다.
- **SC-018**: 처음 지도를 본 수강생 5명 중 4명 이상이 PKM을 현재 업무의 끝으로 오해하지 않고 `결과물 → 정제·저장 → PKM → 다음 업무의 공통 맥락` 순환으로 설명할 수 있다.
- **SC-016**: 1920×1080 화면과 100% 배율에서 노드 내부 스크롤 없이 모든 예시 노드 제목을 읽을 수 있고, 각 사용자 노드의 연결 파일은 마우스를 올리거나 한 번 선택해 확인할 수 있다.

## Assumptions

- 1차 사용자는 강사와 1명의 수강생이며, 둘 다 수업용 컴퓨터의 일반 브라우저에서 지도를 본다.
- 수강생용 학습 템플릿에는 기본 지침과 현재 실습 산출물이 함께 있다. 지도에서는 기본 흐름을 고정 노드로 한 번만 표현하고, 그 흐름에 없던 업무 전용 실행 확장만 별도 노드로 표현한다.
- ‘실시간’은 수업 흐름을 방해하지 않는 5초 이내 자동 반영을 뜻한다. 여러 사용자의 동시 공동 편집은 포함하지 않는다.
- 지원 대상 위치와 파일 유형은 교육 목적에 맞게 미리 정하며, 컴퓨터 전체를 자동 탐색하지 않는다.
- 검증 상태는 파일 존재만으로 추론하지 않고 현재 결과물과 연결된 명시적 근거를 필요로 한다.
- 초기 버전은 데스크톱 수업 화면에 맞추며 모바일 전용 레이아웃은 범위에 포함하지 않는다.
- 기존에 승인한 상세 구조도는 노드 배치·경계·순환 연결의 시각적 기준으로 사용하지만, 그 구조도를 만든 별도 도구를 수강생에게 설치하도록 요구하지 않는다.
- 이 명세는 지도 기능의 요구사항만 다루며, 강의 콘텐츠 원본의 정본 위치와 아루나 사이트 발행 구조는 기존 원칙을 유지한다.
